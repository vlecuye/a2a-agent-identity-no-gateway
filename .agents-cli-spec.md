# Multi-Agent A2A System with Agent Identity Spec

## Overview
A two-agent multi-agent system built using the Agent Development Kit (ADK) where both agents are exposed as A2A services, deployed to Agent Runtime (Reasoning Engine), cataloged in Agent Registry as A2A services, and secured via Agent Identity (SPIFFE ID).
- **Model**: `gemini-3.7-flash` forced to use the `global` region via `GlobalGemini(Gemini)` subclass.
- **Protocol**: A2A protocol over Agent Runtime `/api` passthrough routes (`/a2a/{app_name}/.well-known/agent-card.json`).
- **Catalog**: Registered as `a2a-agent-card` spec type in Google Cloud Agent Registry.
- **Identity**: Deployed with `.agent_engine_config.json` (`AGENT_IDENTITY`).
- **Authorization**: Agent A's SPIFFE principal is granted `roles/aiplatform.user` to invoke Agent B.

## Architecture & Communication Flow
- **Agent A (Coordinator / Caller)**: Receives user queries, runs `gemini-3.7-flash` (global), determines when calculation is needed, and invokes Agent B via `RemoteA2aAgent`.
- **Agent B (Specialist / Callee)**: Exposes A2A endpoints (`/a2a/agent_b/.well-known/agent-card.json`), runs `gemini-3.7-flash` (global), and executes `calculate_formula`.
- **Identity Mechanism**: Each agent is deployed with Agent Identity enabled (`{"identity_type": "AGENT_IDENTITY"}` in `.agent_engine_config.json`).
- **Authorization**: Agent A's SPIFFE principal (`principal://agents.global.org-{ORG_ID}.system.id.goog/resources/aiplatform/projects/{PROJECT_NUMBER}/locations/{LOCATION}/reasoningEngines/{ENGINE_ID_A}`) is granted `roles/aiplatform.user` on the GCP project to authenticate calls to Agent B's Reasoning Engine `/api` passthrough endpoint.

## Example Use Cases
- User asks Agent A: "What is 42 multiplied by 137 plus the square root of 144?"
- Agent A uses `gemini-3.7-flash` (global) and delegates calculation to Agent B via A2A with an Agent Identity-authenticated token.
- Agent B computes the result (`5766`) and returns it via A2A.
- Agent A synthesizes and returns the final explanation to the user.

## Tools Required
- **Agent B**: `calculate_formula` (Internal tool for evaluating arithmetic expressions).
- **Agent A**: `RemoteA2aAgent` referencing Agent B's Agent Runtime A2A Card URL.

## Security & IAM Permissions
- **APIs**: `agentidentity.googleapis.com`, `agentregistry.googleapis.com`, `aiplatform.googleapis.com`, `apphub.googleapis.com`.
- **IAM Binding**:
  ```bash
  gcloud projects add-iam-policy-binding ${PROJECT_ID} \
    --member="principal://agents.global.org-${ORG_ID}.system.id.goog/resources/aiplatform/projects/${PROJECT_NUMBER}/locations/${LOCATION}/reasoningEngines/${ENGINE_ID_A}" \
    --role="roles/aiplatform.user"
  ```

## Agent Registry Registration
```bash
gcloud agent-registry services update agent_b \
  --project="${PROJECT_ID}" \
  --location="${LOCATION}" \
  --display-name="Agent B Calculator Specialist" \
  --agent-spec-type=a2a-agent-card \
  --agent-spec-content=@agent_b/agent_card.json \
  --interfaces="url=${AGENT_B_A2A_URL},protocolBinding=http-json"
```

## Success Criteria
- [ ] Both agents use `gemini-3.7-flash` with the `global` region forced in ADK.
- [ ] Both agents configured with `.agent_engine_config.json` (`AGENT_IDENTITY`).
- [ ] Both agents mount and serve A2A routes on Agent Runtime.
- [ ] Agent B is registered in Agent Registry as an A2A service.
- [ ] Agent A invokes Agent B over A2A authenticated by its SPIFFE identity principal.
